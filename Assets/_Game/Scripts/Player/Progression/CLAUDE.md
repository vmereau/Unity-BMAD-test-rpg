# CLAUDE.md — Assets/_Game/Scripts/Player/Progression

> Loaded when Claude accesses files in this folder. XP, leveling, learning points,
> and skills. **Namespace: `Game.Progression`** (not `Game.Player.Progression`).

---

## What's here & the event chain

These systems are wired together by `GameEventSO` channels, not direct calls:

```
kill → XPSystem.GiveExperience()         (per-enemy XP routed via PlayerRewards)
     → OnXPGained → LevelSystem          (fires OnLevelUp when thresholds crossed)
     → OnLevelUp  → LearningPointSystem   (awards LP per level-up)
                  → PlayerHealth          (AddMaxHealthBonus(ProgressionConfigSO.healthPerLevel): +max and
                                           +current HP, saved via bonusMaxHealth; loads never raise OnLevelUp)
entity death → EntityHealth resolves KillCredit (Scripts/AI) → PersistentID.RegisterDeath(credited) →
     WorldStateManager.RegisterKill (fact always set) → OnEntityKilled (EntityKilled.playerCredited) → PlayerRewards:
     XpOnKill + kill count only if credited; matching PlayerRewardSO bonus always  (spec-kill-xp-credit-assist)
credited knockout → PersistentID.RegisterKnockout → WorldStateManager.RegisterKnockout (first time per
     KilledFact only, claim saved) → OnEntityKnockedOut → PlayerRewards → GiveExperience(
     NPCEntity.XpOnKnockout, countAsKill: false)   (TotalKills unchanged; kill XP still paid on a later death)

LevelSystem → OnPlayerXPProgressChanged  (0–1 in-level progress, raised in Start and
                                          after each XP gain) → ExperienceBarUI (HUD)
```

| File | Role |
|------|------|
| `XPSystem` | Tracks XP + kill count. `GiveExperience(amount)` is the entry point. |
| `LevelSystem` | Subscribes to `OnXPGained`, fires `OnLevelUp` on threshold crossings, then raises `OnPlayerXPProgressChanged`. `CalculateLevelProgress(xp, level, thresholds)` is the public static, tested progress formula. |
| `LearningPointSystem` | Subscribes to `OnLevelUp`, grants Learning Points (LP). |
| `PlayerSkills` | Set of learned skills (learned via tome pickup / other sources). |
| `PlayerRewards` | Pays base kill XP (`Entity.XpOnKill`, player-credited kills only) and knockout XP (`NPCEntity.XpOnKnockout`), then matches its `PlayerRewardSO` list (auto-synced by an Editor tool) against `_onEntityKilled`, `_onDialoguePlayed` and quest started / completed / failed / step-completed events. Applies a `PlayerRewardSO` (XP, LP, gold, stats, then **items** `_itemRewards` = `ItemReward { item, count }` → `InventorySystem.AddItem`, bad entries skipped with a warning). Raises `OnRewardGoldGained` (int) and `OnRewardItemReceived` (pre-formatted `PlayerRewardSO.FormatItemReceived`: "Received: X" / "Received: X ×N") for HUD toasts — reward-only, never for trade / pickups. |

---

## Rules

- Namespace is `Game.Progression` — match it, don't introduce `Game.Player.Progression`.
- Subscribe to event SOs in `OnEnable`, unsubscribe in `OnDisable` — never in `Start`.
- `LevelSystem` raises `OnPlayerXPProgressChanged` once in `Start` and after every XP gain (after `CheckLevelUp`, so the value never exceeds 1). Late listeners miss the startup raise (see `Scripts/UI/HUD/CLAUDE.md`). On load, `PlayerSaveAdapter` calls `LevelSystem.RestoreLevel(level)`, which re-raises it (`RaiseProgress()`).
- `PlayerRewards` data is regenerated by an editor auto-sync (`Scripts/Editor/PlayerRewardsAutoSync.cs`) — don't hand-edit the synced asset.
